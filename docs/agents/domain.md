# Domain docs

## Read before exploring

This repository uses a single-context layout: `GLOSSARY.md` at the root and architecture decision records under `docs/adr/`.

Before domain exploration, read the glossary and ADRs relevant to the affected area. If these files are absent, proceed silently; `/domain-modeling` creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and tests. When a needed concept is missing, reconsider the terminology or note the gap for `/domain-modeling`.

When a proposal conflicts with an existing ADR, identify the ADR and explain why the decision should be reopened rather than silently overriding it.
